# Template syntax

## Choose the variable character

Templates use `@` as their variable character unless another is configured.

```csharp
static readonly QueryCommand AlbumById = new("SELECT AlbumId AS Id, Title FROM albums WHERE AlbumId = @albumId");
```

Choose another character for one command when the provider uses different parameter syntax.

```csharp
static readonly QueryCommand AlbumById = new("SELECT AlbumId AS Id, Title FROM albums WHERE AlbumId = :albumId AND Title = ?:title", ':');

Album album = AlbumById.Query<Album>(cnn, new { albumId = 12 });
```

```sql
SELECT AlbumId AS Id, Title FROM albums WHERE AlbumId = :albumId
```

The chosen character is preserved in generated SQL.

```csharp
public record Filter(int AlbumId, string Title);

var values = AlbumById.StartBuilder();
values.Use(':', nameof(Filter.AlbumId), 12);
values.Use(':', nameof(Filter.Title), "Kind of Blue");
```

```sql
SELECT AlbumId AS Id, Title FROM albums WHERE AlbumId = :albumId AND Title = :title
```

Set the application default once during setup when every new command should use the same character.

```csharp
QueryFactory.DefaultVariableChar = ':';

static readonly QueryCommand AlbumById = new("SELECT AlbumId AS Id, Title FROM albums WHERE AlbumId = :albumId");
```

## Markers inside quoted text are ignored

Variables and markers inside quoted text remain literal text.

```csharp
static readonly QueryCommand QuotedText = new("SELECT '@notAValue' AS Text, \"@notAValue\" AS \"Column\" FROM albums WHERE AlbumId = ?@albumId");

List<DynaObject> rows = QuotedText.Query<List<DynaObject>>(cnn);
```

```sql
SELECT '@notAValue' AS Text, "@notAValue" AS "Column" FROM albums
```

Bracketed and backtick identifiers are also recognized when they appear in provider SQL.

```sql
SELECT [@notAValue] AS Bracketed FROM albums WHERE AlbumId = ?@albumId
SELECT `@notAValue` AS Backticked FROM albums WHERE AlbumId = ?@albumId
```

Without `albumId`, only the real conditional variable is removed.

```sql
SELECT [@notAValue] AS Bracketed FROM albums
SELECT `@notAValue` AS Backticked FROM albums
```

Double-dollar strings are recognized as quoted regions.

```csharp
QueryCommand command = new("SELECT $$ @notAParameter $$ AS Text FROM albums WHERE AlbumId = ?@albumId");
```

Without `albumId`, the marker inside the double-dollar string remains literal.

```sql
SELECT $$ @notAParameter $$ AS Text FROM albums
```

This also works when `$` is the configured variable character.

```csharp
QueryCommand command = new("SELECT $$literal$$ AS Text FROM albums WHERE AlbumId = ?$albumId", '$');
```

Without `albumId`, the quoted text remains and the real condition disappears.

```sql
SELECT $$literal$$ AS Text FROM albums
```

## Markers inside line comments are ignored

```csharp
static readonly QueryCommand Commented = new("SELECT AlbumId AS Id, Title -- ?@ignored and /*Ignored*/ remain comments\nFROM albums WHERE ArtistId = ?@artistId");

List<Album> albums = Commented.Query<List<Album>>(cnn);
```

```sql
SELECT AlbumId AS Id, Title -- ?@ignored and /*Ignored*/ remain comments
FROM albums
```

## Keep a block comment

`/*~` starts a literal block comment. The `~` is removed from the generated SQL.

```csharp
static readonly QueryCommand Commented = new("/*~ generated by the album report */SELECT AlbumId AS Id, Title FROM albums");
```

```sql
/* generated by the album report */SELECT AlbumId AS Id, Title FROM albums
```

An ordinary `/*Key*/` remains a conditional marker.

## Conditions may select incompatible template alternatives

Rinku validates its template syntax, not SQL. This permits an original template whose marked fragments become valid only after one condition combination is applied.

```csharp
static readonly QueryCommand Albums = new("SELECT AlbumId AS Id, Title /*!Archived*/FROM albums /*Archived*/FROM archived_albums ORDER BY AlbumId");
```

While `Archived` is inactive, the query reads from `albums`.

```sql
SELECT AlbumId AS Id, Title FROM albums ORDER BY AlbumId
```

Activating `Archived` switches the query to `archived_albums`.

```sql
SELECT AlbumId AS Id, Title FROM archived_albums ORDER BY AlbumId
```

No SQL parser approves either result inside Rinku. The generated statement is passed to the provider exactly as written.

## Parsing happens when the command is created

Template structure is read once by the `QueryCommand` constructor.

```csharp
QueryCommand invalid = new("SELECT AlbumId AS Id FROM albums WHERE /*Unclosed AlbumId = @albumId");
// RINKU1002 is raised by the constructor.
```

Missing handler values are different. They depend on one execution's supplied values and are raised while that SQL is generated.

```csharp
static readonly QueryCommand AlbumsById = new("SELECT AlbumId AS Id, Title FROM albums WHERE AlbumId IN (@albumIds_X)");

List<Album> albums = AlbumsById.Query<List<Album>>(cnn);
// RINKU2002 is raised before the provider is called.
```
